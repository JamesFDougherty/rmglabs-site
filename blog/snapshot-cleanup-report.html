Find Forgotten VM Snapshots with a Read-Only PowerCLI Report

By RMG LabsNovember 23, 20265 min read

Snapshots are one of the handiest features in vSphere and one of the easiest to forget. Someone takes one before a patch window, the change goes fine, and the snapshot quietly stays behind. Weeks later it has grown, slowed the VM's disk and eaten datastore space nobody budgeted for. A short read-only report that lists every snapshot, its age and its approximate size makes the problem visible, so you can decide what to do about it.

Why Old Snapshots Cause Trouble

A snapshot is not a backup. It records the VM's state at a point in time and then stores every later change in a separate delta file. The longer it sits, the bigger that delta can become, and long snapshot chains can slow disk performance and make consolidation take longer when you finally remove them. They also count against datastore capacity, which is why this report pairs nicely with our datastore capacity report. VMware's general guidance is to keep snapshots short-lived, so the useful question each week is simply: which ones are old?

What the Report Shows

PowerCLI's Get-Snapshot cmdlet returns one object per snapshot with properties including VM, Name, Description, Created, SizeGB and IsCurrent. The script below lists all snapshots older than a number of days you choose, sorted with the oldest first, so the best candidates for a conversation sit at the top. One caution: the size figure is a helpful guide, but it is not always exact, and Broadcom has documented cases where Get-Snapshot reports a size that differs from what vCenter shows. Treat it as a way to spot the big ones, not as an accounting number.

The Script

You need the VMware PowerCLI module and a vCenter account with read access. PowerCLI prompts for your username and password when it connects, and nothing is stored. The script changes nothing; it only reads.

<#
.SYNOPSIS
Lists VM snapshots older than a chosen number of days.
.DESCRIPTION
Reads every snapshot from vCenter and reports the VM, snapshot name,
age in days, creation date and approximate size. Optionally exports
the result to CSV. Read-only: no snapshot is changed or removed.
.NOTES
Author: James Dougherty (scripty)
Version: 1.0
Updated: 2026-11-23
Category: VMware
Requires: VMware PowerCLI
Credentials: Prompts for your vCenter username and password when it runs
Output: Table on screen, optional CSV file
.PARAMETER Server
vCenter server name or address.
.PARAMETER OlderThanDays
Only report snapshots at least this many days old. Default is 7.
.PARAMETER CsvPath
Optional path for a CSV copy of the report.
.EXAMPLE
.\Get-OldSnapshotReport.ps1 -Server vcenter.example.local -OlderThanDays 14
#>
param(
    [Parameter(Mandatory)][string]$Server,
    [int]$OlderThanDays = 7,
    [string]$CsvPath
)

# No credentials are stored in this script: PowerCLI asks for them.
Connect-VIServer -Server $Server | Out-Null

$cutoff = (Get-Date).AddDays(-$OlderThanDays)

$report = Get-VM | Get-Snapshot |
    Where-Object { $_.Created -lt $cutoff } |
    Sort-Object Created |
    ForEach-Object {
        [pscustomobject]@{
            VM          = $_.VM.Name
            Snapshot    = $_.Name
            AgeDays     = [int]((Get-Date) - $_.Created).TotalDays
            Created     = $_.Created
            SizeGB      = [math]::Round($_.SizeGB, 2)
            Description = $_.Description
        }
    }

if ($report) {
    $report | Format-Table -AutoSize
    if ($CsvPath) { $report | Export-Csv -Path $CsvPath -NoTypeInformation }
} else {
    "No snapshots older than $OlderThanDays days were found."
}

Disconnect-VIServer -Server $Server -Confirm:$false

Turning the List Into Action

Resist the urge to delete straight from the report. Each snapshot has an owner and a reason: a change window that has not closed, a developer's rollback point, or a vendor upgrade still being validated. Email the owners, confirm the snapshot is no longer needed and then remove it. PowerCLI's Remove-Snapshot cmdlet supports -WhatIf, so you can preview exactly which snapshots a command would remove before running it for real. Removing a snapshot merges its changes into the base disk, which can take time and generate disk activity, so schedule it outside busy hours.

Make It a Habit

Run the report weekly and save the CSV so you can see whether the list is shrinking. A short snapshot policy helps as much as the script: take them before a change, name them with a ticket number and date, and remove them within a few days.
