ESXi Host Health at a Glance with a Read-Only PowerCLI Report

By RMG LabsNovember 25, 20264 min read

Most vSphere trouble gives a hint before it becomes an outage: a host that dropped out of vCenter, one running hot on memory, or one nobody has rebooted or patched in a year. Clicking through each host in the client works for three hosts and gets old fast at thirty. A small read-only PowerCLI script can put every host in one table, so a daily glance replaces a daily tour.

What to Look At

The objects returned by Get-VMHost already carry the essentials: ConnectionState (Connected, Disconnected, NotResponding or Maintenance), PowerState, NumCpu, CpuUsageMhz and CpuTotalMhz, MemoryUsageGB and MemoryTotalGB, plus Version and Build. Uptime is not a top-level property, but it is available from the host's underlying vSphere data at ExtensionData.Summary.QuickStats.Uptime, reported in seconds. Together these answer the daily questions: is everything connected, is anything close to its limits, and are the hosts running the same build?

The Script

You need the VMware PowerCLI module and a vCenter account with read access. PowerCLI prompts for your username and password when it connects, and nothing is stored. The script only reads; it never puts a host in maintenance mode or changes a setting.

<#
.SYNOPSIS
Reports connection state, CPU and memory use, version and uptime for ESXi hosts.
.DESCRIPTION
Reads every host from vCenter and lists its health at a glance, with
a Flag column for hosts that are not connected or are running high on
CPU or memory. Optionally exports the result to CSV. Read-only: no host
is changed.
.NOTES
Author: James Dougherty (scripty)
Version: 1.0
Updated: 2026-11-25
Category: VMware
Requires: VMware PowerCLI
Credentials: Prompts for your vCenter username and password when it runs
Output: Table on screen, optional CSV file
.PARAMETER Server
vCenter server name or address.
.PARAMETER WarnPercent
CPU or memory use at or above this percent is flagged. Default is 80.
.PARAMETER CsvPath
Optional path for a CSV copy of the report.
.EXAMPLE
.\Get-HostHealthReport.ps1 -Server vcenter.example.local -WarnPercent 85
#>
param(
    [Parameter(Mandatory)][string]$Server,
    [int]$WarnPercent = 80,
    [string]$CsvPath
)

# No credentials are stored in this script: PowerCLI asks for them.
Connect-VIServer -Server $Server | Out-Null

$report = Get-VMHost | Sort-Object Name | ForEach-Object {
    $cpuPct = if ($_.CpuTotalMhz) { [math]::Round(100 * $_.CpuUsageMhz / $_.CpuTotalMhz, 1) } else { $null }
    $memPct = if ($_.MemoryTotalGB) { [math]::Round(100 * $_.MemoryUsageGB / $_.MemoryTotalGB, 1) } else { $null }
    $uptime = $_.ExtensionData.Summary.QuickStats.Uptime
    $flag = if ($_.ConnectionState -ne 'Connected') { 'CHECK STATE' }
            elseif ($cpuPct -ge $WarnPercent -or $memPct -ge $WarnPercent) { 'HIGH USE' }
            else { '' }
    [pscustomobject]@{
        Host       = $_.Name
        State      = $_.ConnectionState
        CpuPercent = $cpuPct
        MemPercent = $memPct
        Version    = "$($_.Version) build $($_.Build)"
        UptimeDays = if ($uptime) { [math]::Round($uptime / 86400, 1) } else { $null }
        Flag       = $flag
    }
}

$report | Format-Table -AutoSize
if ($CsvPath) { $report | Export-Csv -Path $CsvPath -NoTypeInformation }

Disconnect-VIServer -Server $Server -Confirm:$false

Reading the Results

Start with the Flag column. A host showing a state other than Connected deserves attention first, though a host in Maintenance is often intentional, so check your change calendar before worrying. High CPU or memory is a prompt to look closer, not a verdict: a busy host at 85 percent may be fine if the cluster has headroom, and a quiet host at 40 percent may still be a poor place to put one more large VM. The Version column makes uneven patching obvious, since hosts in the same cluster usually should share a build. A very large UptimeDays value can be a reminder that a host has missed its patch window.

Where to Take It Next

Run it each morning and keep the CSV so you can see trends. Pair it with the datastore capacity report and the snapshot report and you have a three-part daily health check that takes a minute to read. If the host list is very large, the trade-offs in our Get-VM versus Get-View comparison apply here as well.
