Build a Datastore Capacity Report with PowerCLI

By RMG LabsNovember 19, 20264 min read

A datastore that quietly fills up is one of the more stressful surprises in a VMware environment. Virtual machines pause, snapshots refuse to grow and the phone starts ringing. The fix for the surprise is boring and effective: look at capacity every day, before it becomes urgent. This how-to builds a small PowerCLI report that does exactly that, and it never changes anything.

What the Report Does

The script connects to vCenter, reads every datastore, works out the percentage of free space and writes a CSV file sorted from fullest to emptiest. Anything below a threshold you choose is flagged, so the rows that need attention are easy to spot. It only reads information, so it is safe to run at any time, including during business hours.

Before You Run It

You need the VMware PowerCLI module installed and a vCenter account that can view datastores; a read-only role is enough. There is nothing else to set up: copy the script, run it, and PowerCLI prompts you for your vCenter username and password. No passwords are stored in the script or in any file.

The Script

<#
.SYNOPSIS
Reports datastore capacity and flags datastores running low on space.
.DESCRIPTION
Connects to vCenter, reads every datastore, calculates percent free
and writes a CSV sorted from fullest to emptiest. Read-only: nothing
is changed.
.NOTES
Author: James Dougherty (scripty)
Version: 1.0
Updated: 2026-11-19
Category: VMware
Requires: VMware PowerCLI
Credentials: Prompts for your vCenter username and password when it runs
Output: CSV report
.PARAMETER Server
vCenter server name or address.
.PARAMETER WarnPercentFree
Datastores with less free space than this percentage are flagged.
.PARAMETER OutFile
Path of the CSV report to write.
.EXAMPLE
.\Get-DatastoreCapacityReport.ps1 -Server vcenter.example.local -WarnPercentFree 20
#>
param(
    [Parameter(Mandatory)][string]$Server,
    [int]$WarnPercentFree = 20,
    [string]$OutFile = ".\datastore-capacity.csv"
)

# No credentials are stored in this script: PowerCLI asks for them.
Connect-VIServer -Server $Server | Out-Null

$report = Get-Datastore | ForEach-Object {
    $pctFree = [math]::Round(($_.FreeSpaceGB / $_.CapacityGB) * 100, 1)
    [pscustomobject]@{
        Datastore   = $_.Name
        CapacityGB  = [math]::Round($_.CapacityGB, 1)
        FreeGB      = [math]::Round($_.FreeSpaceGB, 1)
        PercentFree = $pctFree
        Status      = if ($pctFree -lt $WarnPercentFree) { "LOW" } else { "OK" }
    }
} | Sort-Object PercentFree

$report | Export-Csv -Path $OutFile -NoTypeInformation
$report | Format-Table -AutoSize

Disconnect-VIServer -Server $Server -Confirm:$false

How It Works

Get-Datastore returns each datastore with its capacity and free space in gigabytes. The script turns those two numbers into a percentage, labels each datastore LOW or OK, and sorts so the tightest datastores appear first. The same results go to the screen and to a CSV file, which opens cleanly in Excel for sharing with the team.

Making It a Daily Habit

A report you have to remember to run is only half useful. Schedule the script with Windows Task Scheduler on a management server, point it at a shared folder, and have it run each morning. From there you can add an email step that sends only the rows marked LOW, so a quiet inbox means everything is healthy.

A few practical tips:

  • Pick a threshold that matches how fast your datastores grow. A busy datastore may need a warning at 25 percent free, while a quiet archive can wait until 10.
  • Keep the CSV files for a few weeks. Comparing them shows which datastores are trending toward full, which is more useful than a single snapshot in time.
  • Pair this with the snapshot report from our earlier article. Old snapshots are a common reason datastores fill up.

Where to Go Next

Once the report is trusted, a friendly front end is a natural next step: a small window where a teammate enters the vCenter name, clicks a button and gets the report. The logic stays in the reviewed script, and anyone on the team can run it. If you ever add a step that changes something, such as moving a VM, build it with -WhatIf support so the change can be previewed first.

Read-only scripts like this one are an easy, low-risk way to start automating. They build confidence, save time and make capacity a routine check instead of an emergency.
